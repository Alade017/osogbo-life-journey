# Character models and creation studio

Male and female characters now use a newly authored anatomical sculpt: tapered limbs, connected shoulder and hip transitions, shaped calves and wrists, cheek/jaw planes and revised facial features. The existing surface tessellator builds a continuous smooth-shaded low-poly skin. The shared 18-bone hierarchy, bone names, height convention, movement controller, task poses and equipment sockets remain compatible. The business variant follows the male sculpt; non-binary presentation keeps the existing female-body mapping and its own saved hair palette.

The clothing is rebuilt as a fitted skinned mesh derived from the actual body surface. Sleeve, neckline, trouser and shoe boundaries clip triangles rather than dropping whole faces. Interpolated vertices keep normalized blended bone weights. Three material groups keep garment draw calls bounded, and clothing follows the same skeleton as skin through all eleven existing motions. Body geometry is reused across hair changes, fitted garment geometry is cached per body, and each character retains an independent skeleton and materials. Existing equipment models and saved palette indices remain unchanged. This is fitted clothing, not cloth physics or loose garment simulation.

The creation page now has Appearance, Your Story and Review steps with a shared live preview, drag rotation, keyboard-accessible rotation buttons, idle/walk/dance previews, palette choices, and a final confirmation. Name and integer-age validation gate review; creation keeps the existing authoritative `create_character` RPC and synchronous duplicate-submit guard. Creation defaults and randomized looks include an outfit for every presentation. Existing saved unclothed appearances retain their saved value, and changing presentation does not silently change that choice. Outdated messages claiming skin and hair do not render have been removed.

The layout uses a sticky preview on desktop and normal document flow on mobile. No fixed bottom navigation overlaps the controls. Reduced-motion behavior still comes from the world character renderer. Careers have a retry state without discarding appearance edits, and existing characters redirect to entry instead of creating another character.

Validation includes connected watertight joints across all eight body/build combinations, smooth normals, base mesh budgets, valid skin weights, all eleven motion deformations, independent rig playback, fitted outfit deformation, equipment compatibility and the creation flow. An isolated browser fixture at `scripts/character-studio-browser-check.mjs` bundles the actual page with synthetic queries and no account/database. `STUDIO_BUILD_ONLY=1 node scripts/character-studio-browser-check.mjs` checks its bundle; the full command additionally checks 375px/1280px layouts and captures previews when a local Chrome/Chromium sandbox is permitted. This workspace blocks Chromium sockets, so browser execution and authenticated mobile behavior have not been verified. The offline model render uses the real exported mesh and poses, rather than generated concept art.

The initial model/page rebuild required no database migration. Wearable-item support now requires migration `0109_wearable_outfits.sql`; see `wearable-outfits.md`. Deploying the updated client changes the shared character renderer throughout the game while preserving saved appearance fields and animation state.
