# Neighborhood interaction continuation

World zones now declare which existing service panels they offer. Compact overview cards lead to food/shop catalogues, bank services, career shifts, Buka interiors, district routes, paid hair styling and POS withdrawals. Purchases and shifts keep their existing RPCs; opening a service or selecting an NPC tip never grants money, inventory, XP or need rewards. Authored activities without handlers remain in an informational, collapsed upcoming list without displaying promised rewards as available offers. Adire crafting now has server-owned material consumption, timed jobs and collection receipts; see `adire-crafting.md`. Hot-towel treatments and airtime still need their own authoritative implementations.

Transit estimates use each active destination's persisted fare, duration and allowed modes. The route list includes all active destinations outside the current location. Players select a destination and explicitly confirm before payment. The neighborhood shares the map's travel controller: an in-flight request cannot be submitted twice or dismissed, saved arrival is checked, the destination scene opens, and a confirmed trip with a refresh/navigation failure offers a loading retry without re-running payment. Walking is available when allowed by destination settings. Displayed fares are estimates; the travel RPC owns the final fare and resulting state.

Quick bank actions allow only finite, safe-integer, pure pocket/savings transfers. Synchronous locking blocks duplicate clicks and retries are disabled. A failed response requires refreshing the account, wallet and transaction history before another quick transfer. Successful RPCs invalidate the authoritative wallet, bank-account and transaction caches; no local balance offsets are applied.

Coverage includes service-panel wiring, destination pricing and mode rules, confirmation and arrival routing, no second payment after confirmed travel, duplicate bank-click protection and uncertain bank-response refresh. Existing map-controller, approach-cancellation, bank and travel database tests remain in use. Production build and changed-file lint are checked; the repository still has unrelated TypeScript diagnostics. Hosted database changes and authenticated mobile browser interactions are not claimed by these local checks. The barber/POS follow-up requires migration `0106_barber_pos_services`; see `barber-pos-services.md` for deployment and receipt details.
