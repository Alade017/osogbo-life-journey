# Market stall management fixes

Sold-out owner listings remain valid, visible and editable. Owner stock allows quantities from zero to 999; public listings still require positive available stock. The server retains empty rows so their owner can restock or remove them.

Stock changes now require a saved UUID. Migration `20261121234233_stall_stock_receipts.sql` (Supabase) wraps the existing four-argument inventory-transfer implementation with an authenticated five-argument RPC. The old overload becomes private; do not regrant browser execution. The wrapper locks the character, compares the complete request payload on retries, and commits the inventory change and receipt together. Reusing an ID for different inputs or an unrelated economy operation fails. Existing ownership, rent, price, capacity and inventory checks remain in the original implementation. A confirmed receipt can be recovered even if rent or stock has changed since the operation.

The Market app persists the full stock operation before sending it, blocks further changes while confirmation is unresolved, and offers an explicit retry across phone closure or page reload. Retry sends the same UUID and payload. An uncertain response or failed cache refresh keeps that receipt. Definite rejected operations can be corrected and submitted as new requests. Receipt storage failure prevents submission. Browser storage must remain available for recovery; clearing it before confirmation loses the original request ID.

The stall editor waits for saved details and shows an explicit reload action on failure. The saved badge reads the authoritative profile and lease; the preview and controls show drafts. Saving refreshes the profile before clearing drafts. Untouched fields follow server updates, and changing character remounts the editor and its stock recovery state. Canopy colour remains a local preview.

Deploy the database migration before the updated client. Apply `supabase/migrations/20261121234233_stall_stock_receipts.sql` through the Supabase migration history. There is no Drizzle copy. This depends on the existing stall migration `0077` and its passive-income/discovery dependencies being present. Old clients attempting the non-idempotent four-argument stock RPC will fail closed until refreshed. There is no fallback to that overload.

Coverage includes sold-out owner parsing, private legacy access, repeated stock transfers and removal, changed-payload rejection, ownership, receipt-write rollback, editor errors, saved status, account changes, durable retry, duplicate clicks and cache refresh failures. Local database tests use the existing historical fixture; hosted migration execution and authenticated mobile behavior require deployment verification. Rental prices, passive-income rates, player sale settlement and canopy persistence are unchanged.
