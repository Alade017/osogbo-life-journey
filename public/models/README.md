# OSOGBO LIFE model contract

The development GLBs are original low-poly fixtures generated by `node scripts/generate-development-models.mjs`, not production Blender artwork. They demonstrate actual GLB loading and embedded Idle/Walk clips. Draco decoders are vendored from the installed Three.js package; its MIT license is retained alongside them. Fixture geometry is uncompressed; runtime loading accepts Draco-compressed GLBs using `/models/draco/`.

Place reviewed Blender exports under `characters/`, `city/` and `rooms/`. Export glTF 2.0 binary, apply transforms, use Y-up, meter units and a ground-level character origin. Keep textures small and reuse materials. Name animation clips `Idle`/`Walk` or provide `animationNames` mappings. Rigid hair/accessories may use named attachment sockets; skinned outfits must have matching bone names, hierarchy, inverse bind transforms and bind pose. Arbitrary Mixamo rigs are not automatically retargeted.

`Character` accepts modelPath, position, rotation, scale, currentAnimation and optional modular parts. Cached geometry/textures are shared while skeletons and animation mixers are independent. `WorldScene` accepts a controlled city/room view, city module paths and clickable location records. Parent UI handles authorization and saved travel; switching a loader view alone is not permission to enter a private home.

The main `/map` now uses the 3D adapter, not the Phaser renderer. It preserves Colyseus movement, server checkpoints, interaction distance, district travel and room membership. Server map coordinates remain authoritative: one 3D unit is 40 scene pixels; the 3D origin corresponds to scene pixel (320,300). Building solids must align to each server object: center (object.x, object.y-33), footprint 114×58 pixels. Replacement city art must follow this contract or require a separately reviewed collision migration. The existing authored 2D map artwork is not rendered.

Use `/models` to verify city→room switching and embedded animation independently of economy/private-home permissions. Production home entry still uses its established route and checks. All connected player fixtures currently share one development body; saved appearance/equipment records are preserved but full Blender visual mapping awaits actual modular assets.

Mobile baseline: pixel ratio capped at 1.25, no shadows/postprocessing, low-power context, cached assets, instanced repeated props, and animation transforms outside React. Hidden tabs stop rendering. Performance acceptance needs measured frame times, draw calls and triangle counts on target devices; a small viewport or successful build does not prove a mobile frame-rate target.
