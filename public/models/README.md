# OSUN LIFE model contract

The development GLBs are original low-poly fixtures generated by `node scripts/generate-development-models.mjs`, not production Blender artwork. They demonstrate character and interior GLB loading. Draco decoders are vendored from the installed Three.js package; its MIT license is retained alongside them. Runtime loading accepts Draco-compressed GLBs using `/models/draco/`.

Place reviewed Blender exports under `characters/` and `rooms/`. Export glTF 2.0 binary, apply transforms, use Y-up, meter units and a ground-level character origin. Keep textures small and reuse materials. Name animation clips `Idle`/`Walk` or provide `animationNames` mappings. Rigid hair/accessories may use named attachment sockets; skinned outfits must have matching bone names, hierarchy, inverse bind transforms and bind pose. Arbitrary Mixamo rigs are not automatically retargeted.

The 3D character API accepts semantic animations (`idle`, `walk`, `sit`, `work`, `wave`) and appearance colors/styles. Older models without a requested clip fall back to `Idle`. Set `Character.modelPath` to a full-body variant, or set `appearance.hairPart` / `appearance.outfitPart` to swap modular GLBs; `Character.parts` also accepts additional accessories. Name tintable materials `Skin` and `Outfit`; unrecognized material names keep their authored colors. Use the matching rig for skinned clothing and a named socket such as `Head` for rigid hair. Geometry and textures are shared by the loader cache; each character gets cloned materials so its palette can change independently.

The `/models` development route previews a character inside an interior scene. It does not provide a city map or grant access to private homes.

The `/map` route is a React Three Fiber isometric town scene. Its compact hand-authored layout is in `src/data/osogbo-town.json`; the coordinates are fictional game layout values, not geographic data. Repeated ground cells, roadside trees and cars use instanced meshes. Public venue names are fictional, generic and have no address or real-building association. Sacred and religious sites, real business names, real residence details and actual building footprints are excluded from the active scene. Venue actions still pass through the existing authenticated API and server RPC. The Lantern Club age restriction is stored in `map_landmarks.min_age` and checked by the server.

The map currently uses low-poly GLBs from Kenney's City Kit (Commercial) and City Kit (Suburban) packs. The packs are CC0 and their `License.txt` files remain in their source folders under `city/`. Only the model paths referenced by the town JSON are loaded when the map opens. GLBs follow the pack's glTF 2.0, Y-up, meter-scale contract; no original game or brand assets are included.

## Town map Blender export contract

The R3F town map also accepts these Blender-exported glTF 2.0 binary files directly under this folder: `town.glb`, `compound.glb`, `flat.glb`, and `shophouse.glb`. Export with transforms applied, Y-up, meter units, and compressed Draco or meshopt geometry. `town.glb` should contain only the shared terrain, roads, public greenery, and other non-property scenery; the map places each property model separately from game state. Keep texture dimensions small and reuse materials to limit mobile draw calls.

For tiered property variants, name optional nodes `Accessory_Tier2_Generator` and `Accessory_Tier3_<Name>` (for example, `Accessory_Tier3_WaterTank`). The map shows an accessory only when the supplied property tier is high enough. The `compound`, `flat`, and `shophouse` files should have a ground-level origin and no gameplay data: owner and rent-state labels come only from the map input.

Production home entry still uses its established route and checks. All connected player fixtures currently share one development body; saved appearance/equipment records are preserved but full Blender visual mapping awaits actual modular assets.

## House room Blender export contract

The house screen looks for six room files in `rooms/`: `shared-room.glb`, `single-room.glb`, `studio-flat.glb`, `mini-flat.glb`, `bungalow.glb`, and `duplex.glb`. It renders a simple floor and walls for any missing or unreadable room file. Use a centered, floor-level origin, Y-up, meter units, and applied transforms. Keep walls low enough for the elevated orbit camera to see the furniture. Room dimensions in the current viewer range from roughly 4.2 × 3.4 meters for a shared room to 9.6 × 7.2 meters for a duplex.

The server chooses an included accessory band. Name optional room nodes `Accessory_Tier2_<Name>` and `Accessory_Tier3_<Name>`, for example `Accessory_Tier2_Generator`. Tier 1 nodes need no prefix. Avoid placing furniture on the room model's named slots if it will also appear as a player-placed item.

Player-placed furniture looks for `furniture/<art_key>.glb`, where `<art_key>` comes from the server's `content_items` catalogue. Each file should have a centered origin near floor level and fit approximately within a one-meter slot. Missing or unreadable furniture files appear as small boxes; inventory and placement remain server-owned. Prefer compressed meshes, small textures, and shared materials for mobile browsers.
