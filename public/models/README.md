# OSOGBO LIFE model contract

The development GLBs are original low-poly fixtures generated by `node scripts/generate-development-models.mjs`, not production Blender artwork. They demonstrate character and interior GLB loading. Draco decoders are vendored from the installed Three.js package; its MIT license is retained alongside them. Runtime loading accepts Draco-compressed GLBs using `/models/draco/`.

Place reviewed Blender exports under `characters/` and `rooms/`. Export glTF 2.0 binary, apply transforms, use Y-up, meter units and a ground-level character origin. Keep textures small and reuse materials. Name animation clips `Idle`/`Walk` or provide `animationNames` mappings. Rigid hair/accessories may use named attachment sockets; skinned outfits must have matching bone names, hierarchy, inverse bind transforms and bind pose. Arbitrary Mixamo rigs are not automatically retargeted.

The 3D character API accepts semantic animations (`idle`, `walk`, `sit`, `work`, `wave`) and appearance colors/styles. Older models without a requested clip fall back to `Idle`. Set `Character.modelPath` to a full-body variant, or set `appearance.hairPart` / `appearance.outfitPart` to swap modular GLBs; `Character.parts` also accepts additional accessories. Name tintable materials `Skin` and `Outfit`; unrecognized material names keep their authored colors. Use the matching rig for skinned clothing and a named socket such as `Head` for rigid hair. Geometry and textures are shared by the loader cache; each character gets cloned materials so its palette can change independently.

The `/models` development route previews a character inside an interior scene. It does not provide a city map or grant access to private homes. The `/map` route is a flat geographic map: road, water and terrain layers provide real-world orientation, while interactive places come from active fictional records in the Supabase `locations` table. Real building footprints, businesses, house numbers and religious sites are excluded from the interactive map. MapLibre and source attributions are shown in map controls.

Production home entry still uses its established route and checks. All connected player fixtures currently share one development body; saved appearance/equipment records are preserved but full Blender visual mapping awaits actual modular assets.
